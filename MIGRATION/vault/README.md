# 옵시디언 볼트 기반 이전 전략

## 왜 이 방향인가

계정 이전에서 가장 어려운 문제는 "Claude 세션 67건의 맥락을 어떻게 옮기느냐"였습니다.
**볼트가 이미 있다면 이 문제는 대부분 이미 해결되어 있습니다.**
세션은 휘발성 작업 기록이고, 지식의 영속 저장소는 볼트이기 때문입니다.

그렇다면 이전 작업의 성격이 바뀝니다:

| | 기존 접근 | 볼트 중심 접근 |
|---|---|---|
| 옮길 대상 | Claude 세션 히스토리 (불가능) | 볼트 (평문 마크다운, 완전 이식 가능) |
| 새 계정에서 할 일 | 맥락을 처음부터 재구축 | 볼트를 읽히면 끝 |
| 계정 종속성 | 높음 | **없음** |

즉 방향은 하나입니다: **볼트를 git으로 올려 계정과 완전히 분리하십시오.**
그러면 Claude 계정은 언제든 갈아끼울 수 있는 "연산 자원"이 되고, 지식 자산은 계정 밖에 남습니다.

## 현재 진단 (2026-09-19, 원격 저장소 기준)

접근 가능한 4개 저장소를 전수 확인한 결과 **볼트는 어디에도 없습니다.**

| 저장소 | 내용 | 볼트 |
|---|---|---|
| `Statlab` (private) | 커밋 0 — 완전히 비어 있음 | ✗ |
| `adsense-blog` (private) | Next.js 블로그 (`content/` 45개) | ✗ |
| `kumc-imaging-lab` (public) | 정적 HTML 7개 | ✗ |
| `Bonelab` (public) | 홈페이지 + `Jaykim-org/` 아카이브 | ✗ |

볼트는 로컬 머신에만 있으며 클라우드 동기화(iCloud/Dropbox 등)로 운영 중인 것으로 보입니다.
이 구성에는 세 가지 문제가 있습니다.

1. **계정 이전 시 안전망이 없습니다.** 버전 이력이 없어 되돌릴 수 없습니다.
2. **충돌 사본이 계속 쌓입니다.** 클라우드 동기화의 구조적 한계입니다.
3. **원격 Claude 세션에서 볼트를 읽을 수 없습니다.** 로컬 세션에서만 접근 가능하므로,
   claude.ai/code 나 Routine 같은 자동화가 볼트 지식을 활용하지 못합니다.

git 전환은 세 문제를 동시에 해결합니다.

## 진행 순서

### 1단계 — 진단 (읽기 전용, 안전)

```bash
./inspect-vault.sh                   # 볼트 자동 탐색
./inspect-vault.sh ~/Documents/Vault # 경로 직접 지정
```

확인 항목: 볼트 규모 · 동기화 충돌 사본 · GitHub 용량 한도 초과 파일 ·
민감정보 후보(주민번호·API 키·토큰) · git 관리 여부 · 이중 동기화 위험.

파일을 수정하지 않으므로 부담 없이 먼저 돌려보십시오.

### 2단계 — 정리

진단에서 나온 항목을 해소합니다. 우선순위는 다음과 같습니다.

- **충돌 사본**: 원본과 `diff` 후 병합하거나 삭제. git 전환 전에 반드시 정리합니다.
- **민감정보**: 환자 식별정보·자격증명은 볼트에서 분리합니다.
  git 히스토리에 한 번 들어가면 회수가 사실상 불가능합니다.
- **대용량 파일**: 원본 의료영상(DICOM/NIfTI/WSI)은 볼트 밖 스토리지에 두고
  노트에는 경로만 기록하는 구조를 권장합니다. `gitignore-template` 에 기본 제외 규칙이 있습니다.

### 3단계 — GitHub 비공개 저장소 생성

**반드시 Private 으로 생성하십시오.** 연구·임상 메모가 포함될 수 있습니다.
비어 있는 `Statlab` 을 재활용할 수도 있지만, 용도가 드러나는 이름
(`obsidian-vault` 등)을 새로 만드는 편이 관리에 유리합니다.

### 4단계 — 전환

```bash
DRY_RUN=1 ./init-vault-repo.sh ~/Documents/Vault https://github.com/iioiilloll/obsidian-vault.git
./init-vault-repo.sh ~/Documents/Vault https://github.com/iioiilloll/obsidian-vault.git
git -C ~/Documents/Vault push -u origin main
```

스크립트는 진행 전 4가지를 차단합니다:
충돌 사본 잔존 · 100MB 초과 파일 · 민감정보 패턴 검출 · (경고) 비공개 여부 확인.
민감정보 게이트는 의도적으로 필요할 때만 `ALLOW_SENSITIVE=1` 로 해제할 수 있습니다.

### 5단계 — Obsidian Git 플러그인

설정 → 커뮤니티 플러그인 → "Obsidian Git" 설치 후:

| 설정 | 권장값 | 이유 |
|---|---|---|
| Auto backup after file change | 10분 | 잦은 커밋으로 충돌 범위 최소화 |
| Auto pull on startup | 켜기 | 기기 전환 시 충돌 예방 |
| Auto push | 켜기 | 원격을 항상 최신으로 유지 |

### 6단계 — 클라우드 동기화 해제

**git과 클라우드 동기화를 동시에 쓰지 마십시오.** 두 시스템이 `.git` 디렉터리를 동시에
건드리면 저장소가 손상됩니다. git으로 전환한 뒤에는 볼트를 동기화 폴더 **밖**으로
옮기고, 다른 기기에서는 `git clone` 으로 받으십시오.

## 전환 후 얻는 것

- **계정 이전이 무의미해집니다.** 새 Claude 계정에서 GitHub 연결만 하면 볼트 전체가 따라옵니다.
- **원격 세션에서 볼트를 읽을 수 있습니다.** claude.ai/code 와 Routine 이 볼트 지식을 활용합니다.
  예: 주간 연구 제안 Routine이 볼트의 기존 연구 노트를 참조해 중복을 피할 수 있습니다.
- **충돌 사본이 사라집니다.** git merge 가 클라우드 동기화의 "둘 다 남기기"를 대체합니다.
- **이력이 남습니다.** 언제 무엇을 바꿨는지 추적되고, 실수는 되돌릴 수 있습니다.
